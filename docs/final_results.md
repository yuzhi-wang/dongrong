# 最终结果与交付说明

## 结论

历史频率重排已删除。当前流程为：客户贷前信息 → 本地硬规则过滤 → Qwen从候选中直接返回Top3 → 关联真实放贷产品统计命中。真实标签不参与推荐，产品历史出现次数不参与评分。

当前Qwen使用 `qwen3.8-max`，默认16路并行；提示词只维护一套System/User文件。推荐JSON只保留Top3列表及必要详情，不输出完整排名或重复的重排元数据。

提示词能够改善条件解释和候选取舍，但现有资料缺失与多产品同时匹配也会限制复现历史放贷结果的能力。此次未证明能单靠提示词回到此前约70%的结果；旧成绩包含已撤销的历史频率重排。

Qwen参照为23:15:47至23:26:08的全量回测：93位客户，86条成功、5条结构失败、2条硬过滤排除。Astra对93位完成对话内复核，先保存推荐，再关联标签；两条被硬过滤排除的真实产品同样计为未命中。

## 提示词修正与资料问题

原提示词对本行工资路径笼统要求核对“金额和持续月数”。但融e借客群1仅规定工行代发、在职满6个月、工资金额至少5000元，并未规定连续代发6个月。最新Qwen的C007、C114、C159、C161、C171补出了6个月代发要求；C054使用在职时长推断代发时长，C087把未规定的代发月数作为待核项。

当前提示词已修正：只检查本产品、本路径明文要求的条件；在职、社保、公积金和代发各自的时长不得互相复制；未规定的条件不自行补齐。本次条件对象修正尚未重新进行Qwen真实回测。

其余需要持续遵守的原则：必要条件、补充信息、门槛放宽、明文辅助偏好和客户需求分别处理；同一事实不重复加分；不以“客户看起来更优质”奖励产品；未知不等于满足或冲突。

现有资料仍有以下限制：

- 93位客户的公积金月数、城市和客群身份字段全部为空；6位社保月数为空，19位工资银行为空。
- 闪电贷、网捷贷和苏农e贷存在残缺的公积金或客群路径条件。此次确认的是当前JSON问题，尚未核对原Excel是否已有缺失。
- 缺少白名单、实际报价、实际可批额度和渠道可办性。“可考虑加白”不表示已进入白名单，公开产品上限不表示客户实际能获得。
- 多款产品同时符合公开条件时，历史记录仅说明最终放贷的一家，不证明其他候选不合理。需要更多业务证据才能稳定区分第三名附近的产品。
